# Python 离线分析脚本更新记录 (2026-04-23)

## 1. 发现的问题
正如您所指出的，在处理今天和昨天抓取的 ADC 原始数据（Raw CSV）时，由于固件中硬编码写入了 `sample_rate_hz = 64000`，但实际物理采样率表现为 `32 kSPS`。
这导致之前生成的频谱图中，Python 脚本错误地以 64 kHz 作为基准来计算频率轴（X轴），进而导致：
- 原本物理上在 1000 Hz / 1200 Hz 附近的信号峰，在图上被拉伸到了 2000 Hz / 2400 Hz 附近。
- 标线（Markers）仍然死死画在 1000 Hz 和 1200 Hz，导致看起来“找错了频点”、“标线对应位置是空的”。

## 2. 刚刚完成的修改

为了在不立即重编固件的情况下，能够立刻出正确的图并分析已有数据，我对 `Python_code` 目录下的三个核心脚本进行了热修复：

### 2.1 修改 `plot_adc_raw_wave_fft.py` (FFT 出图脚本)
- **默认采样率修正**：当从 CSV 读取 `sample_rate_hz` 时，如果没有覆盖，现在默认 fallback 采用 `32000.0` 替代原本的 `64000.0`。
- **兼容性修复 (KeyError)**：修复了由于不同抓包命令输出的 CSV 表头不同，导致找不到 `stage` 字段而崩溃的 bug。
- **命令行参数支持**：该脚本本已提供 `--fs-override` 参数，现在通过 `python plot_adc_raw_wave_fft.py --input <...> --fs-override 32000.0` 可以完美地将旧数据的 X 轴缩放回真实的物理频率。

### 2.2 修改 `plot_adc_raw_wave_psd.py` (PSD 出图脚本)
- **默认采样率修正**：同样地，在读取 raw csv 时，将默认采样率的安全后备值从 `64000.0` 变更为 `32000.0`。
- **表头兼容性增强**：引入了与 FFT 脚本相同的 `if "stage" in row:` 防护逻辑，解决了直接运行该脚本报错 `KeyError: 'stage'` 的问题。现在可以稳定生成正确的 PSD 频谱图。

### 2.3 修改 `analyze_dpmzm_open_loop_scan.py` (开环数据分析脚本)
- **采样率覆盖**：修改 `summarize_raw_rows` 函数，强制将提取的 `sample_rate_hz` 默认值从 `64000.0` 修正为 `32000.0`。
- **核心影响**：这确保了当调用 `goertzel_magnitude` 时，使用的 `omega`（角频率）是基于真实的 `32 kSPS` 计算的，使 Python 端离线提点的幅度能够真正对准真实的物理频点，从旧的 Raw CSV 中抢救出有效曲线。
