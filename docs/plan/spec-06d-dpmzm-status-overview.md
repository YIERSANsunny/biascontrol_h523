## 2. DPMZM 最终目标

当前 DPMZM 路线的最终目标，不是“在旧 MZM 固件里临时加几个命令”，而是建立一套完整的 DPMZM 偏压控制链路。

### 2.1 近程目标：开环实验固件

先做一套 DPMZM 开环实验固件，支持：

- 三路偏压：`I / Q / P`
- 双导频：`fI / fQ`
- 多频测量：
  - `fI`
  - `fQ`
  - `|fI-fQ|`
  - `fI+fQ`
- 三类扫描：
  - `I/Q MATP`
  - `P QTP`
  - `I/Q MITP`
- 统一串口输出：
  - `DPMZMCSV`
  - `DPMZMRAW`
  - `DPMZMSUM`

### 2.2 中程目标：板上解释层

在开环扫描跑通之后，再增加板上解释层，例如：

- MATP 主解 / 隐式解区分
- QTP 主判据 / 辅判据融合
- MITP 分支区分
- 工作点候选分类与筛选

### 2.3 远程目标：自动闭环控制

最终再进入真正的 DPMZM 自动控制阶段，例如：

- 顺序锁定 `I-MATP -> Q-MATP -> P-QTP -> I-MITP -> Q-MITP`
- 板上自动扫描与阶段切换
- 板上闭环 PID 或更高层控制器

## 3. 当前开发原则

当前 DPMZM 路线有一个重要约束：

**尽量不破坏原有 MZM 主线逻辑。**

更具体地说：

- `app_main.c` 保留为主入口
- `ctrl_bias.c` 保留为 MZM 控制主循环
- `ctrl_modulator_mzm.c` 保留为 MZM 策略实现

DPMZM 通过平行新增文件的方式推进，而不是大面积侵入旧 MZM 主线。

这样做的目的很明确：

- 不把已经验证过的 MZM 路径改坏
- DPMZM 可以单独演进
- 方便后续回退、对比、拆分

### 4.7 连续导频链路的演进

这一部分已经经历了数次明显迭代：

1. **主循环空转驱动**
   - 依赖主循环速度
   - 不是可信的频率输出
   - 已废弃

2. **TIM6 + `sinf()` + 中断里 blocking SPI**
   - 比主循环版明显更好
   - 但中断负担重
   - DAC 更新抖动仍然明显

3. **TIM6 + LUT + SPI1 TX DMA**
   - 当前最新实现
   - 采用相位累加控制频率
   - LUT 用来替代逐点 `sinf()`
   - SPI1 发送改成 TX DMA
   - 连续导频链路更接近“稳定连续输出”

对应文件：

- `app/inc/app_main_dpmzm.h`
- `app/src/app_main_dpmzm.c`
- `drivers/src/drv_callbacks.c`

### 4.8 扫描时序重构

当前扫描时序已经从“每个 ADC 点都重写一次 DAC”的旧方式，推进到更合理的结构：

1. 切换到新的扫点 `bias_I / bias_Q / bias_P`
2. 只更新一次基准偏压
3. 等待 `settle`
4. 连续导频运行
5. ADC 连续采一整段样本
6. Goertzel / FFT 对整段数据提取频点
7. 输出 `DPMZMCSV / DPMZMSUM`
8. 切到下一个扫点

已经额外修掉两个关键问题：

- 扫描导频不再依赖先手动 `pilot-open on`
- 扫描结束后，工作点会恢复到扫描前的 `I/Q/P`

这说明当前实现已经明显更接近理想扫描流程。

## 5. 最近新增确认的阶段性进展

### 5.1 raw 观测链路的主矛盾已经不是“采样率是不是错了”

前一阶段最关键的问题，是 raw FFT 与示波器 / 频谱仪对不上，导致很多扫描结果不可信。

现在这一层问题已经基本被校正：

- 电脑端 FFT 脚本已支持目标频点附近的局部峰值搜索
- raw 频谱主峰位置已经能够与示波器 / 频谱仪观测结果对应起来
- 当前不再把“raw 采样率错了 / bin 盯错了”当成主矛盾

这意味着：

- raw 观测链路已经从“需要先校准”推进到“可以支持真实开环实验”
- 后续矛盾已经转向工作点解释、交调不对称、分支选择等更高层问题

### 5.2 开环扫描阶段已经完成

截至 2026-04-24，我们已经不只是“命令能跑”，而是已经完成了完整的开环扫描实验阶段：

- `I/Q MATP` 可以稳定实扫并出图
- `P QTP` 可以稳定实扫并出图
- `I/Q MITP` 可以稳定实扫并出图
- 可以沿某一条分支做连续细扫 / 超细扫迭代
- 可以把扫到的候选点重新设回板上继续下一轮扫描

更重要的是，当前已经形成了完整实验闭环：

1. 设置固定工作点
2. 执行单路扫描
3. 保存串口日志 / CSV
4. 电脑端出图
5. 根据极小值重新设置偏压
6. 继续下一轮细扫

这说明 DPMZM 的“开环扫描阶段”已经完成，进入下一阶段的条件已经具备。

### 5.3 已经得到一组强阶段性候选工作点

基于 `2026-04-24` 的细扫 / 超细扫结果，当前最强阶段性候选点为：

- `I = +5.130 V`
- `Q = -6.020 V`
- `P = +1.070 V`

其中：

- `P=+1.070 V` 是按 `QTP` 主判据 `mag_fsum_2200` 自动落点
- 如果按 `200 Hz` 与 `2200 Hz` 联合平衡，`P≈+1.080 V` 也值得保留

需要保留的实验注记是：

- 最后一次 `Q-MITP` 超细扫的最小点落在左边界 `Q=-6.020 V`
- 这说明负 `Q` 分支的真实最优点有可能还在更负一点的位置

也就是说，当前最准确的表述不是“最终点已经完全定死”，而是：

- 开环扫描阶段已完成
- 当前已经有一组很强的阶段性最优候选点

## 6. 当前最关键的未决问题

### 6.1 `0.2 kHz` 和 `2.2 kHz` 为什么仍然明显不对称

这仍然是当前最值得继续追的物理问题。

目前已经能稳定观测到：

- `200 Hz` 与 `2200 Hz` 的共同谷底
- 但两者的深度往往仍然不完全一致
- 很多工作点下，`200 Hz` 与 `2200 Hz` 的抑制程度明显不对称

当前可能原因仍包括：

- `200 Hz` 混入低频拍频、包络项或不平衡项
- `2200 Hz` 被 `2fI / 2fQ` 等邻近二次项压住
- 工作点本身不在真正最优组合上

这件事已经不再是“观测链路完全错了”，而是“现象已经站住，但机理还没完全解释清楚”。

### 6.2 负 `Q` 分支的最优点还需要窗口外确认

虽然当前负 `Q` 分支已经收敛到：

- `Q ≈ -6.020 V`

但最后一次超细扫的最小点落在左边界，这意味着：

- 当前得到的是“当前窗口内最优”
- 还不能完全等同于“该分支全局局部最优已经确认”

这会直接影响：

- `P-QTP` 的最终落点
- `I-MITP` 的下一轮精扫窗口

### 6.3 板上解释层还没有建立

虽然开环扫描已经完成，但当前板上仍然主要是在“测量并输出数据”，还没有把这些数据解释成更高层语义。

还缺的解释能力包括：

- MATP 主解 / 隐式解区分
- MITP 分支自动区分
- QTP 主判据 / 辅判据融合
- 工作点候选自动筛选与排序

## 7. 当前尚未完成的内容

### 7.1 还没有闭环控制

当前已经完成的是开环扫描阶段，不是闭环控制阶段。

未完成项：

- 自动顺序锁定
- 自动切换阶段
- 自动锁定三路工作点
- DPMZM 闭环 PID 或更高层控制器

### 7.2 还没有完整的板上解释层

当前板上会输出数据，但还没有板上自动解释这些数据。

未完成项：

- MATP 主解 / 隐式解区分
- MITP 分支自动区分
- QTP 主判据 / 辅判据融合
- 工作点自动筛选

### 7.3 `MITP` 仍然没有独立物理解读

当前代码里：

- `MATP` 和 `MITP` 对 `I/Q` 仍共用同一套一阶最小判据
- `scan mitp ...` 目前更像“在特定工作点附近重新扫一遍一阶局部极小”
- 还不是一个已经完成分支判定与物理解读的 MITP 识别器

这意味着：

- 图上的谷底是真实实验极小值
- 但还不能直接等同于“代码已经理解了 MITP 的物理意义”

### 7.4 `settle` 还没有被系统验证

当前默认：

- `settle_ms = 2`

这一步虽然存在，但还没被系统扫过：

- `2 ms` 是否真的够
- `10 ms / 20 ms` 是否会明显改善曲线平滑度和交调深度

### 7.5 正 / 负 `Q` 分支还没有做最终归一比较

当前 2026-04-24 的主要收敛路线是沿负 `Q` 分支推进的。

还没有完成的事情是：

- 用统一判据，把正 `Q` 分支和负 `Q` 分支的最终候选点做严格对比
- 给出“哪一支更值得作为后续自动化起点”的最终结论

## 9. 下一步最值得优先做的事情

### 9.1 先把负 `Q` 分支彻底扫实

最优先建议不是重新大范围乱扫，而是：

1. 固定当前 `I=+5.130 V`
2. 固定当前 `P=+1.070 V`
3. 再向更负方向补一轮 `Q-MITP` 小窗口超细扫
4. 根据新的 `Q` 值再做一轮窄窗口 `P-QTP`

这样可以先把当前这条已经接近收敛的负 `Q` 分支真正坐实。

### 9.2 之后补做正 / 负 `Q` 分支总对比

等负分支窗口外确认结束后，下一步最值得做的是：

- 用统一导频幅度
- 用统一扫描参数
- 对比正 `Q` 分支与负 `Q` 分支
- 给出哪一支的 `QTP / MITP` 联合表现更优

### 9.3 再进入板上解释层与自动化

开环阶段完成后，下一阶段最自然的工作就是：

- 把“图上看出来的结论”变成“板上能自动解释的规则”

也就是从：

- “人工看图做实验”

- “板上自动筛点并进入闭环”

2026-04-29 的阶段状态已经比本文前半部分更进一步。当前不再只是“开环扫描完成”，而是已经形成了三层可运行能力：

2. `dpmzm auto fine`：基于粗扫结果执行宽窗 + 小窗细扫，得到更可信的 `I/Q/P` 局部候选点。
3. `dpmzm lock probe/step/start/stop/status`：基于小扰动有符号误差做低速闭环守点。

当前固件新增了独立闭环模块：

- `control/inc/ctrl_lock_dpmzm.h`
- `control/src/ctrl_lock_dpmzm.c`

闭环控制目前采用保守低速策略：

```text
probe delta      = 0.05 V
max step         = 0.01 V
deadband         = 0.03
lock sequence    = P -> I -> P -> Q -> P
main metrics     = I:fI, Q:fQ, P:fI+fQ
```

当前脚本层还固定了一套已经人工验证过的“正 P 分支复现流程”：

```text
set I/Q/P = 0/0/0 V
dpmzm auto coarse
dpmzm auto fine
restore first positive P branch from fine logs
small P-QTP -> small I-MITP -> small Q-MITP -> small P-QTP
dpmzm lock start
```

对应脚本：

- `tools/run_dpmzm_positive_branch_flow.py`
- 外部实验副本：`C:\Users\Administrator\Desktop\DPMZM_contral_bais\Python_code\run_dpmzm_positive_branch_flow.py`

这一步的关键经验是：自动流程必须显式规定粗扫起点。若直接继承上一次实验的最终偏压，粗扫可能被带到另一条分支，导致 `auto fine` 在扩窗阶段返回 `NEED_WIDER_WINDOW`。因此脚本默认会先将 `I/Q/P` 归零，再开始粗扫；如需从当前板上状态继续实验，可显式加 `--skip-initial-bias`。
