## 2. DPMZM 最终目标

当前 DPMZM 路线的最终目标，不是“在旧 MZM 固件里临时加几个命令”，而是建立一套完整的 DPMZM 偏压控制链路。

### 2.1 近程目标：开环实验固件

先做一套 DPMZM 开环实验固件，支持：

- 三路偏压：`I / Q / P`
- 双导频：`fI / fQ`
- 多频测量：
  - `fI`
  - `fQ`
  - `|fI-fQ|`
  - `fI+fQ|`
- 三类扫描：
  - `I/Q MATP`
  - `P QTP`
  - `I/Q MITP`
- 统一串口输出：
  - `DPMZMCSV`
  - `DPMZMRAW`
  - `DPMZMSUM`

### 2.2 中程目标：板上解释层

在开环扫描跑通之后，再增加板上解释层，例如：

- MATP 主解 / 隐式解区分
- QTP 主判据 / 辅判据融合
- MITP 分支区分
- 工作点候选分类与筛选

### 2.3 远程目标：自动闭环控制

最终才进入真正的 DPMZM 自动控制阶段，例如：

- 顺序锁定 `I-MATP -> Q-MATP -> P-QTP -> I-MITP -> Q-MITP`
- 板上自动扫描与阶段切换
- 板上闭环 PID 或更高层控制器

## 3. 当前开发原则

当前 DPMZM 路线有一个重要约束：

**尽量不破坏原有 MZM 主线逻辑。**

更具体地说：

- `app_main.c` 保留为主入口
- `ctrl_bias.c` 保留为 MZM 控制主循环
- `ctrl_modulator_mzm.c` 保留为 MZM 策略实现

DPMZM 通过平行新增文件的方式推进，而不是大面积侵入旧 MZM 主线。

这样做的目的很明确：

- 不把已经验证过的 MZM 路径改坏
- DPMZM 可以单独演进
- 方便后续回退、对比、拆分

### 4.7 导频常开模式的演进

这一部分已经经历了三次明显迭代：

1. **早期主循环空转驱动**
   - 依赖主循环速度
   - 不是真正可控的频率输出
   - 已废弃

2. **TIM6 + `sinf()` + 中断里 blocking SPI**
   - 比主循环版明显更好
   - 但中断负担重
   - DAC 更新时序抖动仍然明显

3. **TIM6 + LUT + SPI1 TX DMA**
   - 当前最新实现
   - 用相位累加控制频率
   - LUT 代替逐点 `sinf()`
   - SPI1 发送改成 TX DMA
   - 连续导频链路明显更接近“真正连续输出”

当前实现不是片上 DAC 那种极限硬件连续波，但已经比旧方案干净很多。

对应文件：

- `app/inc/app_main_dpmzm.h`
- `app/src/app_main_dpmzm.c`
- `drivers/src/drv_callbacks.c`

### 4.8 扫描时序重构

这是当前阶段最重要的新进展之一。

旧扫描模式的问题是：

- 每个 ADC 点前都会更新一次 DAC
- 导频生成、偏压更新、ADC 采样耦合过紧
- 很容易把 DAC 阶梯跳变、SPI 干扰、暂态响应一起采进 ADC

当前已经改成更合理的扫描节奏：

1. 切换到新的扫点 `bias_I / bias_Q / bias_P`
2. 只更新一次基准偏压
3. 等待 `settle`
4. `TIM6` 连续输出 `I/Q` 导频
5. ADC 连续采一整段样本
6. Goertzel / FFT 对整段数据提频点
7. 输出 `DPMZMCSV / DPMZMSUM`
8. 切到下一个扫点

对应当前实现，已经额外修掉两件关键 bug：

- 扫描导频不再偷偷依赖先手动 `pilot-open on`
- 扫描结束后，工作点会恢复到扫描前的原始 `I/Q/P`

这说明当前实现已经明显更接近理想扫描流程。

## 5. 当前尚未完成的内容

### 5.1 还没有闭环控制

当前仍然只有开环扫描。

未完成项：

- 自动顺序锁定
- 自动切换阶段
- 自动锁定三路工作点
- DPMZM 闭环 PID 或更高层控制器

### 5.2 还没有完整的板上解释层

当前板上会输出数据，但还没有板上自动解释这些数据。

未完成项：

- MATP 主解 / 隐式解区分
- MITP 分支自动区分
- QTP 主判据 / 辅判据融合
- 工作点自动筛选

### 5.3 `MITP` 仍然没有独立物理解读

这是当前代码中的一个明确缺陷。

现在 `MATP` 和 `MITP` 对 `I/Q` 仍然共用同一套一阶最小判据：

- `I` 路都看 `mag_fI`
- `Q` 路都看 `mag_fQ`

也就是说：

- 代码能把整条曲线扫出来
- 也能找出局部谷底 / 全局最小
- 但还不能自动判定哪个谷底属于真正的 `MITP`

因此当前图上的谷底是真实测到的局部极小值，但还不是已经完成物理解读的最终工作点。

### 5.4 连续导频还不是极限硬件连续波

虽然连续导频已经升级到 `TIM6 + LUT + SPI1 TX DMA`，但当前仍然不是“片上 DAC + DMA”那种零 CPU 参与的极限形态。

还可继续优化的方向包括：

- 进一步降低 `CS/LDAC` 收尾带来的软件参与
- 评估更高更新率或更长 LUT 的收益
- 视实验结果再决定是否值得继续向更彻底的 DMA/LUT 引擎演进

### 5.5 `settle` 仍未验证充分

当前扫描默认仍是：

- `settle_ms = 2 ms`

这一步在旧工程里一直就有，但对当前 DPMZM 链路是否足够，还没有被充分验证。

## 6. 当前最关键的未决科学问题

### 6.1 现象

当前实测里，一个非常关键的问题仍然没有彻底搞清楚：

**为什么 `0.2 kHz` 和 `2.2 kHz` 明显不对称。**

理想情况下：

- `0.2 kHz = |fI-fQ|`
- `2.2 kHz = fI+fQ|`

它们都来自同一个乘积项：

\[
\sin(\omega_I t)\sin(\omega_Q t)
= \frac{1}{2}\cos(\omega_I-\omega_Q)t
- \frac{1}{2}\cos(\omega_I+\omega_Q)t
\]

因此在理想模型下，二者通常应当同源、同阶、幅度接近。

但实测里看到的是：

- `0.2 kHz` 往往明显更强
- `2.2 kHz` 往往明显更弱
- `2.2 kHz` 附近还常出现 `2.0 kHz` 和 `2.4 kHz`

### 6.2 当前已经确认的事实

目前已经确认：

1. 这不只是 FFT 分辨率问题
   - `RBW = 10 Hz` 和 `RBW = 8.33 Hz` 的原始 FFT 已经足够把 `2000 / 2200 / 2400 Hz` 分开

2. `2200 Hz` 附近确实存在邻近二次谐波
   - `2fI = 2000 Hz`
   - `fI+fQ = 2200 Hz`
   - `2fQ = 2400 Hz`

3. 某些偏置点下，`2200 Hz` 的确弱于 `2000 / 2400 Hz`

4. 某些固定工作点下，`200 Hz` 和 `2200 Hz` 在 raw FFT 里都可能被淹没
   - `200 Hz` 接近噪声 / 杂散底
   - `2200 Hz` 夹在 `2000 / 2400 Hz` 之间

这说明：并不是“代码里单独读错了 `2200 Hz`”，而更像是物理链路里的真实可观测性本来就差。

### 6.3 当前最可能的解释

当前最合理的中间判断是：

- `0.2 kHz` 里混入了更多低频非理想贡献
  - 拍频
  - 包络
  - 幅度不平衡
  - 慢漂
  - DAC / 调制器非理想

- `2.2 kHz` 更接近真正的和频交调项
  - 但在真实链路里更弱
  - 而且被 `2fI / 2fQ` 等邻近二次谐波夹住

所以：

- `0.2 kHz` 往往更“好看”
- 但不一定更“干净”
- `2.2 kHz` 往往更弱
- 但更像真实 `QTP` 主判据

### 6.4 还没有最终证明的点

还没有彻底证明：

- `0.2 kHz` 到底有多少比例来自真正差频交调
- `0.2 kHz` 有多少比例来自额外拍频 / 杂散 / 包络
- `2200 Hz` 被压低的主因到底是哪一个：
  - `2fI`
  - `2fQ`
  - 频响不平衡
  - 失真项
  - 工作点本身不理想

## 7. 当前仍需排除的工程问题

### 7.1 ADC 配置是否真的生效

驱动当前会写：

- `OSR = 128`
- 目标 `64 kSPS`

但初始化后还没有做最终寄存器读回确认。

因此仍需排除：

- `CLOCK` 寄存器是否真的生效
- 实际 `DRDY` 周期是否确实约 `15.625 us`

### 7.2 导频真实输出质量是否足够干净

仍需排除：

- `1.2 kHz` 这一路是否比 `1 kHz` 更容易带来二次谐波
- 问题是跟着“频率”走，还是跟着“通道”走
- `I/Q` 两路导频幅度和失真是否明显不平衡

### 7.3 新扫描时序是否已经足够干净

当前实现已经比旧扫描方式合理很多，但这仍然是一个**待验证假设**，还不是最终结论。

我们目前只能说：

- 新实现更符合工程直觉
- 但它是不是当前问题的主因，还必须通过 A/B 实验去验证

### 7.4 `settle_ms` 是否过短

当前默认 `2 ms`。

在真实 DPMZM 链路下，仍需排除：

- 偏压切换后模拟链路是否尚未完全稳定
- `2 ms` 是否不足以建立稳态

## 8. 明天最值得优先做的验证

### 8.1 新旧导频链路的 A/B 对比

目标：

- 判断 `TIM6 + LUT + SPI1 TX DMA` 是否显著改善了 `2200 Hz` 的可观测性

方法：

- 固定同一工作点
- 复扫同一条 `P-QTP`
- 对比旧结果与新结果：
  - `2200 Hz` 是否更干净
  - `2000 / 2400 Hz` 是否下降
  - 曲线是否更稳定

### 8.2 `settle = 2 / 10 / 20 ms` 对比

目标：

- 判断偏压切换后未稳定是否仍是重要污染源

方法：

- 固定同一条扫描
- 只改 `settle_ms`
- 比较曲线和 raw FFT 是否明显变干净

### 8.3 固定偏压下同时观察 `200 / 2200 / 2000 / 2400 Hz`

目标：

- 判断 `2200 Hz` 是否被邻近二次谐波压制

方法：

- 固定 `I/Q/P`
- 抓长原始 ADC
- 比较：
  - `200 Hz`
  - `2200 Hz`
  - `2000 Hz`
  - `2400 Hz`

### 8.4 示波器与 ADC 观测同一点

目标：

- 判断“示波器看得到 `2.2 kHz`，ADC 却看不清”到底是观测点问题还是 ADC 链路问题

方法：

- 尽量让示波器探头直接挂在 ADC `CH0` 对应输入节点
- 与 ADC raw FFT 同步对比

## 9. 当前阶段一句话总结

当前 DPMZM 已经从“代码骨架阶段”进入了“真实实验链路验证阶段”。

理论、仿真、固件、串口、扫描、FFT 这些基础能力已经具备；今天最大的工程进展是：

- 扫描结束恢复原工作点
- 连续导频升级到 `TIM6 + LUT + SPI1 TX DMA`

当前最核心的未决问题，不再是“代码能不能跑”，而是：

**在新的连续导频链路下，`0.2 kHz` 与 `2.2 kHz` 的不对称现象是否会得到更可信的解释。**

同时必须保持一个清醒判断：

**我们当前认为“更合理”的实现，不等于已经被证明“就是正确答案”。**

后续仍然必须依赖 A/B 对照和同点观测来验证。
