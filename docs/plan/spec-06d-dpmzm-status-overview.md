## 2. DPMZM 最终目标

当前 DPMZM 路线的最终目标不是“在旧 MZM 固件里临时加几个命令”，而是建立一套完整的 DPMZM 偏压控制链路。

### 2.1 近程目标：开环实验固件

先做一版 DPMZM 开环实验固件，支持：

- 三路偏压：`I / Q / P`
- 双导频：`fI / fQ`
- 多频检测：
  - `fI`
  - `fQ`
  - `|fI-fQ|`
  - `fI+fQ`
- 三类扫描：
  - `I/Q MATP`
  - `P QTP`
  - `I/Q MITP`
- 统一串口输出：
  - `DPMZMCSV`
  - `DPMZMRAW`
  - `DPMZMSUM`

### 2.2 中程目标：板上解释层

在开环扫描跑通之后，再增加板上解释层，例如：

- MATP 主解 / 隐式解区分
- QTP 主判据 / 辅判据融合
- MITP 分支区分
- 工作点候选分类与筛选

### 2.3 远程目标：自动闭环控制

最终才进入真正的 DPMZM 自动控制阶段，例如：

- 顺序锁定 `I-MATP -> Q-MATP -> P-QTP -> I-MITP -> Q-MITP`
- 板上自动扫描与阶段切换
- 板上闭环 PID 或更高层控制器

## 3. 当前开发原则

当前 DPMZM 路线有一个重要约束：

**尽量不破坏原有 MZM 主线逻辑。**

更具体地说：

- 原 `app_main.c` 保留为主入口
- 原 `ctrl_bias.c` 保留为 MZM 控制主循环
- 原 `ctrl_modulator_mzm.c` 保留为 MZM 策略实现

DPMZM 通过并行新增文件的方式推进，而不是大面积侵入旧 MZM 主线。

这样做的目的很明确：

- 不把已经验证过的 MZM 路径改坏
- DPMZM 可以单独演进
- 方便后续回退、对比、拆分

### 4.8 最近新增：扫描模式的导频时序重构

这是本阶段最重要的新进展之一。

之前扫描模式的实现是：

- 每采一个 ADC 点
- 软件前台更新一次导频 DAC
- 立刻等 `DRDY`
- 再读 ADC

这种模式非常容易把：

- DAC 阶梯跳变
- SPI 写入数字扰动
- 模拟链路未稳定瞬态

一起采进 ADC，从而污染：

- `200 Hz`
- `2200 Hz`
- 以及附近的 `2000 / 2400 Hz`

现在已经改成：

- 扫描时复用 `TIM6` 连续导频链路
- 扫描逻辑只更新 `I/Q/P` 的**基准偏压**
- `I/Q` 导频由定时器持续输出
- ADC 在连续导频下采样

当前判断：

- 这是**更合理的工程实现**
- 但它是不是根因、是不是最终正确方案，仍需通过 A/B 实验验证

### 5.3 还没有最终硬件映射冻结

### 5.5 `MATP` / `MITP` 仍未做分支解释

这是当前代码中的一个明确缺陷。

现在 `MATP` 和 `MITP` 的主判据仍然是：

- `I` 路都看 `mag_fI`
- `Q` 路都看 `mag_fQ`

也就是说：

- 代码能把整条曲线扫出来
- 也能找出局部谷底 / 全局最小
- 但**还不能自动判断哪个谷底属于真正的 MATP，哪个属于 MITP，哪个只是周期副解或隐式解**

所以目前图上的谷底：

- 是真实测到的局部极小值
- 但还不是已经被代码正确“物理解读过”的最优工作点

## 6. 当前最关键的未决科学问题

### 6.1 现象

当前实测里，一个非常关键的问题仍然没有彻底搞清楚：

**为什么 `0.2 kHz` 和 `2.2 kHz` 明显不对称。**

理想情况下：

- `0.2 kHz = |fI-fQ|`
- `2.2 kHz = fI+fQ`

二者都来自同一个乘积项：

\[
\sin(\omega_I t)\sin(\omega_Q t)
= \frac{1}{2}\cos(\omega_I-\omega_Q)t
- \frac{1}{2}\cos(\omega_I+\omega_Q)t
\]

因此在理想模型下，二者通常应当同源、同阶、幅度接近。

但实测里看到的是：

- `0.2 kHz` 往往明显更强
- `2.2 kHz` 往往明显更弱
- `2.2 kHz` 附近还常出现 `2.0 kHz` 与 `2.4 kHz`

### 6.2 当前已经确认的事实

目前已经确认：

1. **这不只是 FFT 分辨率问题。**
   - 在 `6400` 点、`64 kSPS` 下，`RBW = 10 Hz`
   - 在 `7680` 点下，`RBW = 8.33 Hz`
   - 已经足够把 `2000 / 2200 / 2400 Hz` 分开

2. **`2200 Hz` 附近确实存在邻近二次谐波。**
   - `2fI = 2000 Hz`
   - `fI+fQ = 2200 Hz`
   - `2fQ = 2400 Hz`

3. **某些偏置点下，`2200 Hz` 确实弱于 `2000 / 2400 Hz`。**
   - 不是单纯因为分辨率不足而“糊掉”
   - 而是它在频谱上本来就更弱

4. **`200 Hz` 很可能混入了更多非理想贡献。**
   - 低频拍频
   - 幅度不平衡
   - 包络起伏
   - 慢漂移
   - DAC / 调制器非理想

5. **有些固定工作点下，raw FFT 里 `200 Hz` 和 `2200 Hz` 都被淹没。**
   - `200 Hz` 接近噪声 / 杂散底
   - `2200 Hz` 夹在 `2000 / 2400 Hz` 中间
   - 这意味着这类工作点并不适合直接用 raw FFT 去判断 `QTP`

### 6.3 当前最可能的解释

当前最合理的中间判断是：

- `0.2 kHz` 不是纯净的理想差频交调项，里面混入了更多低频非理想分量
- `2.2 kHz` 更接近真正的和频交调项，但在实际链路中被 `2fI / 2fQ` 等二次谐波夹住，而且本身偏弱

所以：

- `0.2 kHz` 往往“更好看”
- 但不一定“更干净”
- `2.2 kHz` 往往更弱
- 但反而更像真正的 `QTP` 主判据

### 6.4 当前还没最终证明的点

还没有彻底证明：

- `0.2 kHz` 到底有多少比例来自真实差频交调
- `0.2 kHz` 有多少比例来自额外拍频 / 杂散 / 包络
- `2.2 kHz` 被压低的主因到底是哪一个：
  - `2fI`
  - `2fQ`
  - 频响不平坦
  - 失真项
  - 工作点本身不理想

## 7. 还需要排除的工程问题

除了上面的科学问题，当前还有几类工程问题需要明确排除。

### 7.1 ADC 配置是否真的生效

当前驱动会写：

- `OSR = 128`
- 目标 `64 kSPS`

但初始化后还没有做最终寄存器读回确认。

因此仍需排除：

- `CLOCK` 寄存器是否真的生效
- 实际 `DRDY` 周期是否真是 `15.625 us`
- ADC 是否有可能运行在错误采样率

### 7.2 导频真实输出质量是否足够干净

需要继续排除：

- `1.2 kHz` 是否比 `1 kHz` 更容易带来二次谐波
- 问题是跟着“频率”走，还是跟着“通道”走
- `I/Q` 两路导频幅度和失真是否明显不平衡

### 7.3 旧扫描时序是否曾显著污染频谱

这是当前新增加的关键怀疑项。

旧扫描模式里：

- 每个 ADC 点前都会重写导频 DAC
- DAC 更新和 ADC 采样时序耦合过紧

这很可能引入：

- 阶梯波谐波
- SPI 数字扰动
- 未稳定瞬态

当前已经改成“连续导频 + 每扫点更新基准偏压”的模式，但：

**这是不是根因，仍需 A/B 实验验证。**

### 7.4 偏压切换后的 `settle` 是否足够

`settle` 不是新加的，原工程里就一直有：

- 扫描起点大步进：`1000 ms` 预稳定
- 每步小步进：`2 ms`

当前 DPMZM 扫描默认仍然是：

- `req.settle_ms = 2 ms`

但在真实 DPMZM 链路下，`2 ms` 可能偏短。

需要继续排除：

- 偏压切换后 ADC 是否过早采样
- `2 ms` 是否不足以让链路稳态建立

## 8. 当前最值得优先做的验证

### 8.1 做新旧扫描方式的 A/B 对比

目标：

- 判断旧的“逐样本写 DAC”是不是确实污染了 `200 / 2200 Hz`

方法：

- 固定同一工作点
- 旧扫描方式和新扫描方式分别扫一次
- 比较：
  - `2200 Hz` 是否更干净
  - `2000 / 2400 Hz` 是否下降
  - `QTP` 曲线是否更稳定

### 8.2 验证 `200 / 2200 / 2000 / 2400 Hz` 的联动关系

推荐实验：

- 固定 `Q、P`，细扫 `I`
- 同时记录：
  - `200 Hz`
  - `2000 Hz`
  - `2200 Hz`
  - `2400 Hz`

目标：

- 看 `2200 Hz` 是不是跟 `2000 / 2400 Hz` 一起起伏
- 看它是不是被邻近谐波主导

### 8.3 验证 `P` 对 `2200 Hz` 的专属性

推荐实验：

- 固定 `I/Q`
- 细扫 `P`
- 同时记录：
  - `200 Hz`
  - `2000 Hz`
  - `2200 Hz`
  - `2400 Hz`

目标：

- 如果 `2200 Hz` 明显随 `P` 变化，而 `2000 / 2400 Hz` 相对稳定
- 则说明 `2200 Hz` 仍保留较强的 `P-QTP` 判据意义

### 8.4 增大 `settle_ms` 做对比

推荐实验：

- 同一条扫描
- 分别使用：
  - `2 ms`
  - `10 ms`
  - `20 ms`

目标：

- 看曲线是否明显变干净
- 判断偏压切换未稳定是否是重要来源

### 8.5 用示波器与 ADC 观测同一点

目标：

- 判断“示波器能看到 `2.2 kHz`，ADC 却看不到”到底是处理问题还是观测点问题

方法：

- 探头直接挂到 ADC `CH0` 实际输入同一节点
- 和 ADC raw FFT 同步对照

## 9. 当前状态一句话总结

当前 DPMZM 代码和实验已经进入“真实链路可扫、可采、可分析”的阶段。

理论、仿真、固件、串口、扫描、FFT 这些基础能力已经具备。

现在最核心的未决问题，不再是“代码能不能跑”，而是：

**如何正确解释真实链路里 `0.2 kHz` 与 `2.2 kHz` 的不对称，以及哪一种扫描/观测方式才真正可信。**

同时需要保持一个清醒判断：

**我们当前认为“更合理”的实现，不等于已经被证明“就是正确答案”。**

后续必须继续用 A/B 对照和同点观测去验证，而不是直接把当前工程直觉当成结论。
